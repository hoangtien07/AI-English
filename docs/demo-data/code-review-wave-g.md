# Wave G final review — open-data enrichment foundation

Review date: 2026-09-11. Scope was limited to the C1–C3, D1, E1–E2, and F1–F2 enrichment changes: v2 contracts/enums, OER adapter/registry/downloader, importer, canonical source register/docs, and their tests/reviews. Unrelated pre-existing auth, Flutter generated-plugin, Docker, and dev-local changes were not reviewed.

## Verdict

**Not ready for the next task (pinned lexical snapshots + generated course artifact) until the two High findings are resolved.** The offline OER boundary itself is correctly fail-closed: its canonical provenance URL is constrained, remote downloader entry is rejected before HTTP, and the approval register blocks OER without an immutable snapshot. This is **not a playable demo pack**: no approved OER snapshot or generated course artifact is supplied, the register explicitly blocks the curriculum source, and no learner-facing/demo execution path was reviewed or created.

## Verified behavior and review notes

- Source-record/manifest OER provenance checks are exact on host, path, query, and fragment ([contracts.py:33-46](../../ai-service/api/services/content_etl/contracts.py), [contracts.py:248-287](../../ai-service/api/services/content_etl/contracts.py), [contracts.py:346-377](../../ai-service/api/services/content_etl/contracts.py)).
- The registry independently normalizes/decode-checks paths and blocks noncanonical URLs ([registry.py:240-293](../../ai-service/api/services/content_etl/registry.py)); the generic downloader rejects OER before any resolver or HTTP transport call ([downloader.py:75-80](../../ai-service/api/services/content_etl/downloader.py)).
- Adapter output is deterministic for equivalent input order and is bounded/sanitized: 4 MiB snapshot limit, 10,000 records, 100 scope items, 5,000 characters, control/markup rejection, and metadata-only HTML extraction ([oer_curriculum.py:46-68](../../ai-service/api/services/content_etl/adapters/oer_curriculum.py), [oer_curriculum.py:224-332](../../ai-service/api/services/content_etl/adapters/oer_curriculum.py)). HTML checksum verification intentionally removes only the checksum meta tag; JSON canonicalization excludes the checksum declaration ([oer_curriculum.py:97-120](../../ai-service/api/services/content_etl/adapters/oer_curriculum.py)).
- The importer is local-path bounded and uses a single outer async transaction around create/preview/apply ([import_approved_course_artifact.py:51-115](../../backend-service/scripts/import_approved_course_artifact.py), [import_approved_course_artifact.py:227-240](../../backend-service/scripts/import_approved_course_artifact.py)). Its fixed register exact allowlist blocks the OER entry as intended ([import_approved_course_artifact.py:127-191](../../backend-service/scripts/import_approved_course_artifact.py), [open-data-source-register-v1.json:46-56](open-data-source-register-v1.json)).
- No license/security conclusion depends on a network lookup. The review makes no claim that upstream OER rights are approved beyond the repository’s declared `CC-BY-4.0` metadata and its blocked-register status.
